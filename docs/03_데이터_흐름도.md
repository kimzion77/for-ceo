## 2. 검토 요청 — 데이터 흐름 (Request 시퀀스)

### 임금명세서 검토 예시

```mermaid
sequenceDiagram
    autonumber
    participant U as 사용자
    participant N as Next.js
    participant B as BFF
    participant A as FastAPI
    participant S as ws.services.analyze
    participant R as ws.repository
    participant D as master.db
    participant L as LLM

    U->>N: 임금명세서.png 업로드 + 계약유형·산정연도
    N->>B: POST /api/cgr/ws/extract (multipart)
    B->>A: POST /api/v1/ws/extract (+ X-API-Key)
    A->>A: parse_to_text (OCR/파서)
    A-->>N: { extracted_text }

    N->>B: POST /api/cgr/ws/analyze<br/>{ wage_text, business_size, contract_type,<br/>pay_period_year, pay_cycle, ... }
    B->>A: forward
    A->>S: analyze.run(...)
    S->>R: get_minimum_wage(2025)
    R->>D: SELECT FROM minimum_wage_master
    D-->>R: 10,030원 / 209h 환산
    R-->>S: { hourly_amount, monthly_amount_209h }
    S->>S: prompt 빌드 (slot 카탈로그 + 컨텍스트 주입)
    S->>L: chat.completions (temperature=0)
    L-->>S: JSON (riskLevel·overallStatus·results·...)
    S->>S: _strip_slot_codes (post-process)
    S->>S: llm_cache.put
    S-->>A: analysis_result
    A-->>N: { analysis_result, elapsed_sec, model }

    N->>N: updateWs(caseId, { phase: 'result', analysisResult })
    N-->>U: 결과 페이지로 라우팅

    Note over U,L: "표준 임금명세서 생성" 클릭 →

    U->>N: 생성 버튼
    N->>B: POST /api/cgr/ws/generate<br/>{ analysis_result, wage_text, user_overrides }
    B->>A: forward
    A->>S: generate.run(...)
    S->>L: chat.completions
    L-->>S: 표준 본문 텍스트
    S-->>A: wage_text
    A-->>N: { wage_text }
    N-->>U: /review/[id]/ws/contract 로 이동
```

## 4. 영속화 흐름 (DB 기록 단위)

| 사용자 액션 | 기록되는 행 |
|---|---|
| 사업장 등록 | `workplace` (1 행, business_no SHA-256 hash) |
| 근로자 등록 | `employee` (1 행, emp_no hash + name 마스킹) |
| 임금명세서 업로드 | `payslip_document` (1 행, doc_uid 부여) |
| OCR 추출 | `payslip_ocr_raw` (N 행 — field 단위) |
| 사용자 확정 | `payslip` (1 행) + `payslip_line` (N 행) |
| 룰엔진 실행 | `inspection_run` (1 행, ruleset_version 박힘) |
| 위반 탐지 | `violation_finding` (N 행 — 룰당 1개) |
| 권고 생성 | `recommendation` (N 행, rendered_text) |
| 사용자 수정 | `correction_log` (N 행) |
| LLM 비계산적 판단 | `llm_judgment` (N 행 — 통상임금 분류 등) |
| 검토 결과 (취업규칙·근로계약서) | `audit_case` + `audit_finding` |
| 모든 LLM 호출 | `backend/data/llm_cache/` (SHA-256 키 → JSON) |
| 모든 사용자 방문 | `backend/data/access_log.jsonl` |

## 5. 외부 LLM 호출 — 비식별 게이트

```mermaid
flowchart TD
    REQ["LLM 호출 요청"]
    REQ --> Q1{"이 호출에 PII<br/>포함 가능?"}
    Q1 -->|"yes"| MASK["mask_pii<br/>(향후 Phase)"]
    Q1 -->|"no"| SEND["바로 송신"]
    MASK --> SEND
    SEND --> LLM["OpenAI / Dauri"]
    LLM --> CACHE["llm_cache.put"]
    CACHE --> RES["응답"]

    style Q1 fill:#fef9c3
    style MASK fill:#fee2e2
```

**현재**: 사업장·근로자 식별자는 DB 저장 시 해시. 본문 텍스트는 그대로 LLM 송신 (베타 한정).
**계획**: 본문에서 이름·주민번호·연락처를 추출 마스킹 후 LLM 호출.

## 7. 도커·배포 시 데이터 경로 (참고)

운영 시 환경변수로 override 가능:

| 환경변수 | 기본 | 용도 |
|---|---|---|
| `CGR_MASTER_DB` | `backend/data/master.db` | SQLite 파일 경로 |
| `API_KEY` | secrets.toml | 일반 API 키 |
| `ADMIN_API_KEY` | secrets.toml | 관리자 API 키 |
| `ADMIN_PASSWORD` | secrets.toml | Streamlit 로그인 |
| `NEXT_PUBLIC_API_BASE` | `http://localhost:8503` | 프론트→백엔드 |
| `CGR_API_KEY` | (서버측만) | BFF→백엔드 |
