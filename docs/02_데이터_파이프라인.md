## 2. 문서별 파이프라인

### 2-1. 근로계약서 (Employment Contract)

```mermaid
flowchart TD
    U["사용자: 근로계약서 파일 업로드<br/>+ 사업장 규모, 근로자 유형(다중)"]
    U --> EXT["POST /api/v1/ec/extract<br/>이미지면 Vision OCR / 기타는 파서"]
    EXT -->|"extracted_text"| STR["POST /api/v1/ec/structure<br/>LLM이 8섹션 JSON으로 구조화"]
    STR -->|"structured_data"| REV["검토 페이지 Step2<br/>사용자가 표 UI에서 수정"]
    REV -->|"확정 structured_data"| ANA["POST /api/v1/ec/analyze<br/>33-매핑 위반 분석 (LLM)"]
    ANA -->|"analysis_result"| RES["결과 페이지 Step3<br/>VerdictBlock·FindingCarousel·SuggestBlock"]
    RES -->|"user_overrides"| GEN["POST /api/v1/ec/generate<br/>표준 계약서 본문 생성"]
    GEN -->|"contract_text"| CTR["계약서 페이지 Step4<br/>편집·다운로드"]

    style EXT fill:#E5ECF8
    style STR fill:#E5ECF8
    style ANA fill:#fff7e0
    style GEN fill:#d1fae5
```

**EC 의 특징**
- 4 단계 명시 (extract → structure → analyze → generate)
- Step2 검토 페이지에서 사용자가 표를 수정 가능
- 33-매핑 (공통/5인이상/기간제/단시간/일용직/연소자/외국인) 분기
- 챗봇 (`/ec/chat`) 으로 결과 후속 질문

### 2-2. 임금명세서 (Wage Statement)

```mermaid
flowchart TD
    U["사용자: 임금명세서 파일 업로드<br/>+ 사업장규모, 계약유형(단일), 지급주기, 산정기간"]
    U --> EXT["POST /api/v1/ws/extract<br/>OCR / 파서"]
    EXT -->|"extracted_text"| BR{"분석 트랙<br/>분기"}
    BR -->|"판단형"| ANA["POST /api/v1/ws/analyze<br/>11 슬롯 위반 분석 (LLM)<br/>최저임금 자동 주입"]
    BR -->|"계산형 (Phase 7-B)"| INS["POST /api/v1/ws/inspect<br/>구조화 payslip → 룰엔진<br/>V001·V002·V010"]
    ANA -->|"analysis_result"| RES["결과 페이지<br/>VerdictBlock·캐러셀·SuggestBlock"]
    RES -->|"user_overrides"| GEN["POST /api/v1/ws/generate<br/>표준 임금명세서 본문"]
    GEN -->|"wage_text"| CTR["수정본 페이지<br/>편집·복사·다운로드"]

    INS -.->|"persist=true"| DB["inspection_run<br/>violation_finding<br/>recommendation"]

    style EXT fill:#E5ECF8
    style ANA fill:#fff7e0
    style INS fill:#fee2e2
    style GEN fill:#d1fae5
```

**WS 의 특징**
- 11 슬롯 (단일 그룹 — 33-매핑 없음)
- LLM 분석 (`/analyze`) + 계산형 룰엔진 (`/inspect`) 이원 트랙
- 산정 대상 연도 → 마스터 DB 에서 해당 연도 최저임금 자동 주입
- 계약 유형 단일 선택 (정규/기간제/단시간/일용)

### 2-4. 노무제공자 계약서 (Service Provider Contract) — Phase 17

특수형태근로종사자(특고)·플랫폼 종사자 등 도급·위임 관계 검토. EC 와 유사한 3 단계, generate 단계 없음.

```mermaid
flowchart TD
    U["사용자: 노무제공자 계약서 업로드<br/>+ 사업장규모"]
    U --> EXT["POST /api/v1/sc/extract<br/>OCR / 파서"]
    EXT -->|"extracted_text"| STR["POST /api/v1/sc/structure<br/>LLM 이 4 섹션·16 슬롯 JSON 으로 구조화"]
    STR -->|"structured_data"| REV["검토 페이지 Step2<br/>worker_subtype 선택 + 슬롯별 표 수정"]
    REV -->|"확정"| ANA["POST /api/v1/sc/analyze<br/>슬롯별 위반 분석<br/>(LLM + prohibited_patterns)"]
    ANA -->|"analysis_result"| RES["결과 페이지<br/>16 슬롯 카드 리스트 + 종합·시정 권고"]
    RES -.->|"표준 양식"| LINK["가이드 → form_template<br/>고용노동부 자료실 외부 URL"]

    style EXT fill:#E5ECF8
    style STR fill:#E5ECF8
    style ANA fill:#fff7e0
    style LINK fill:#d1fae5
```

**SC 의 특징**
- 16 슬롯 카탈로그 — `atomic_slots_sc.yaml` (Phase 17 신설)
- worker_subtype (`산재적용_특고16` / `고용보험_노무제공자19` / `플랫폼종사자` / `기타_도급`) 컨텍스트가 사회보험 슬롯 평가에 결정적
- "근로자성 위장 방지" — 종속성 강화 표현(`출근 시간 준수`, `취업규칙 준수` 등) 을 `prohibited_patterns` 로 검출
- generate 단계 없음 — 표준 양식은 고용노동부 자료실 외부 URL 로 안내(가이드 `form_template`)
- 신규 법령 6개 등록: 산재보험법, 고용보험법, 산업안전보건법, 민법 일부

### 2-5. 꿀팁 가이드 (Reference, 정적 조회) — Phase 16

문서 업로드·OCR·LLM 없음. **정적 reference DB → 사업주 자율점검 보조**.

```mermaid
flowchart TD
    SEED["Excel: 영세사업주를 위한 꿀팁.xlsx<br/>(15 시트, ~340 행)"]
    SEED --> FILT["시드 단계 필터<br/>FRM020~024 (분쟁 서식 5건)<br/>ORG004/005/015~019/021 (분쟁 기관 8건)<br/>→ 완전 제외"]
    FILT --> DB[("master.db<br/>11 가이드 테이블<br/>(283 행)")]
    DB --> API["/api/v1/guide/* (12 엔드포인트)<br/>기본 필터:<br/>audience IN ('employer','both')<br/>AND excluded_from_service = 0"]
    API --> UI1["/guide 페이지<br/>8 탭 (개요·의무·서식·공식·용어·기관·비치·FAQ)"]
    API --> UI2["홈 미리보기<br/>HomeGuidePreview<br/>(KPI 4 + 규모별 의무 6건)"]
    API --> UI3["검토 결과 ↔ 가이드<br/>V001~V010 ↔ wage_calc_formula<br/>cross-link"]
    DB --> ADM["Streamlit 관리자<br/>10_📘_가이드DB.py<br/>8 탭 + 자율점검 원칙 안내"]

    style SEED fill:#E5ECF8
    style FILT fill:#FFF8E1,stroke:#F4C430
    style API fill:#d1fae5
```

**가이드 도메인의 특징**
- **자율점검 원칙** — 진정·구제·노동위원회 등 분쟁 경로 데이터 13건 시드 단계 사전 제외
- 방어 필터 이중화 — `excluded_from_service` 컬럼 + API 기본 audience 필터
- `wage_calc_formula.related_violation_code` FK — 룰엔진 V001~V010 위반 결과에서 가이드 공식으로 직링크
- `size_threshold_duty` 의 SIZE_RANK 누적 — 5인 이상 사업장은 1인+ 의무까지 모두 노출
- `form_template.download_url` 은 고용노동부 자료실 외부 URL (호스팅 안 함 / Phase 18 에서 채움)

## 3. 룰엔진 + LLM 하이브리드 (임금명세서)

```mermaid
flowchart TB
    IN["구조화 payslip + workplace 컨텍스트"]
    IN --> RULE["룰엔진 (rule_engine.py)"]

    subgraph RULE
        R1["V001 필수기재 누락<br/>(성명·지급일·총액·라인 검사)"]
        R2["V002 최저임금 미달<br/>(통상임금합 ÷ 근로시간 vs 마스터)"]
        R10["V010 공제내역 미분리<br/>(DEDUCTION 라인 수 검사)"]
    end

    RULE --> FIND["ViolationFinding[]"]
    FIND --> PER{"persist?"}
    PER -->|"true"| DB["inspection_run<br/>violation_finding<br/>recommendation"]
    PER -->|"false"| RET["응답만 반환"]

    IN -.->|"LLM 트랙 별도"| LLM["LLM analyze<br/>11 슬롯 적절성 판단"]
    LLM -->|"V009 통상임금 분류 등<br/>judgment_kind='llm'"| FIND

    style RULE fill:#fee2e2
    style LLM fill:#fff7e0
    style DB fill:#d1fae5
```

**계산 결정성** — 같은 PayslipIn → 같은 ViolationFinding 리스트.
`ruleset_version` 컬럼에 박혀 시점 재현 가능.

## 5. 시드 파이프라인 (마스터 DB 초기화)

`backend/scripts/seed_master_db.py` 8 단계:

```mermaid
flowchart LR
    S1["1. 스키마<br/>db/schema.sql<br/>38 테이블 + 4 뷰"]
    S2["2. document_type<br/>4 행<br/>(WR·EC·WS·SC)"]
    S3["3. topic + topic_section<br/>data/topic_corpus.json<br/>31 + 5 주제·1779 섹션"]
    S4["4. check_item from yaml<br/>EC 35·WR 115·WS 11·SC 16<br/>= 177 슬롯"]
    S5["5. 33-매핑 (EC 전용)<br/>category·topic·law 링크"]
    S6["6. WS topic/law 링크<br/>(YAML meta 필드 직접)"]
    S7["7. 임금 룰 마스터<br/>seed_wage_masters<br/>최저임금·임금항목·V001~V010·권고"]
    S8["8. 꿀팁 가이드 (Phase 16)<br/>seed_guide_db.py<br/>11 테이블·283 행<br/>(분쟁 13건 제외)"]

    S1 --> S2 --> S3 --> S4 --> S5 --> S6 --> S7 --> S8
```

명령: `cd backend && python scripts/seed_master_db.py --drop-first`

`--drop-first` 는 audit 데이터(`audit_case`, `inspection_run` 등) 도 비움.
유지하려면 `--drop-first` 없이 — UPSERT 만 적용.

**Step 8 (꿀팁 가이드)** 의 시드 제외 로직 — `seed_guide_db.py` 내 상수:
```python
EXCLUDED_FORM_CODES = {"FRM020", "FRM021", "FRM022", "FRM023", "FRM024"}  # 진정·구제 서식
EXCLUDED_ORG_CODES = {"ORG004", "ORG005", "ORG015", "ORG016",
                      "ORG017", "ORG018", "ORG019", "ORG021"}              # 노동위·검찰 등
```
자율점검 본질을 지키기 위해 Excel 행이 있어도 DB 에 INSERT 하지 않음.

## 6. 캐시·이력 흐름

```mermaid
flowchart LR
    REQ["LLM 호출 (system+user+schema)"]
    REQ --> KEY["llm_cache.make_key<br/>(SHA-256 hash)"]
    KEY --> HIT{"cache hit?"}
    HIT -->|"yes"| RET["캐시된 응답"]
    HIT -->|"no"| LLM["OpenAI 호출"]
    LLM --> PUT["llm_cache.put"]
    PUT --> RET
    RET --> LOG["data/access_log.jsonl<br/>(서비스·액션·timestamp)"]
    RET --> HIST["data/review_history.jsonl<br/>(취업규칙 결과)"]
```

캐시 stats: 현재 1,667+ 항목 (`backend/data/llm_cache/`).
