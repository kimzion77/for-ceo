# 01 · 시스템 개요

## 무엇을 하는 서비스인가

**영세사업장 자율점검 서비스**는 사업주가 자신의 노동법 관련 문서를 올리면
누락·위반·보완사항을 분석하고, 시정 권고와 표준 양식을 제공하는 AI 도구.

검토 대상 3 문서:
1. **취업규칙** (work_rules) — 10인 이상 사업장 작성·신고 의무 (근기법 §93)
2. **근로계약서** (employment_contract) — 모든 사업장 (근기법 §17)
3. **임금명세서** (wage_statement) — 모든 사업장 (근기법 §48 + 시행령 §27-2)

---

## 설계 원칙

### 1) 결정성·재현성 (최상위 요건)

"같은 입력 → 같은 출력" 을 시스템 차원에서 보장.

| 어떻게 | 어디에 |
|---|---|
| `temperature=0`, `top_p=1` | 모든 LLM 호출 |
| LLM 응답 캐시 (입력 hash → 결과) | `cgr/llm_cache.py` |
| 룰셋 버전 박힘 | `inspection_run.ruleset_version` |
| 최저임금 기준연도 박힘 | `inspection_run.minimum_wage_year` |
| 슬롯 카탈로그 = 마스터 DB 단일 소스 | `cgr/db/schema.sql` |
| 시드 스크립트로 재현 가능 | `backend/scripts/seed_master_db.py --drop-first` |

### 2) 룰 + LLM 하이브리드

**계산형 위반** (시급 9,500 vs 최저시급 10,030원, 가산수당 부족 등) → **코드 룰**
**판단형 위반** (이 수당이 통상임금인가) → **LLM 판단**

`violation_type.judgment_kind` 컬럼이 분기 키. 10개 위반 카탈로그 중 9개 `rule`, 1개 `llm`.

### 3) PII 보호 — 비식별화 경계

| 데이터 | 처리 |
|---|---|
| 사업자번호 | SHA-256 hash (`business_no_hashed`) |
| 사원번호 | SHA-256 hash (`emp_no_hashed`) |
| 성명 | 마스킹 (`홍길동` → `홍○○`) (`name_masked`) |
| 임금명세서 본문 | OCR 텍스트 그대로 (외부 LLM 호출 시) — **로컬 비식별 후 외부 LLM** 은 후속 Phase |
| OpenAI / Dauri SAMI GPT 외부 호출 | 비식별 데이터만 전송 |

### 4) 마스터 DB = 단일 소스 (Single Source of Truth)

이전엔 YAML·JSON 이 분산. Phase 1~3 에서 SQLite 마스터 DB 로 통합.
- 슬롯 카탈로그 — `check_item` (161 행)
- 주제 코퍼스 — `topic_section` (1,779 행)
- 법령 조문 — `law_article` (56 행)
- 룰·권고 — `violation_type` · `recommendation_mapping`
- 트랜잭션 — `workplace` · `employee` · `payslip` 등

## 시스템 구성 (3-tier)

### Tier 1 — 사용자 인터페이스

**Next.js Frontend** (port 3000)
- App Router, 클라이언트 컴포넌트
- Pretendard Variable 폰트, civic 디자인 토큰
- 검토 흐름: 홈 (문서종류 + 업로드 + 사업장정보) → 로딩 → 결과 (게이지·캐러셀·SuggestBlock) → 표준 문서 생성

**Streamlit 관리자** (port 8502)
- 9 페이지 (파이프라인 순서: 마스터DB → 슬롯편집 → 프롬프트 → 검토이력 → 데이터관계 → 모델비교 → 캐시 → 시스템설정 → 방문통계)
- 홈 대시보드는 9 단계 파이프라인 플로우 카드

### Tier 2 — API 백엔드

**FastAPI** (port 8503) — `cgr.api.main:app`

| 라우터 | 엔드포인트 | 책임 |
|---|---|---|
| `routes.review` | `POST /api/v1/review` | 취업규칙 검토 |
| `routes.ec` | `POST /api/v1/ec/{extract,structure,analyze,generate,chat}` | 근로계약서 4단계 + 챗봇 |
| `routes.ws` | `POST /api/v1/ws/{extract,analyze,inspect,generate}` + `GET /catalog` | 임금명세서 (LLM analyze + 계산형 inspect + generate) |
| `routes.topics` | `GET /api/v1/topics/corpus` | 노무사회 코퍼스 (1,779 섹션) |
| `routes.slots` | `GET/PUT /api/v1/slots/...` | 슬롯 카탈로그 (관리자) |
| `routes.master_db` | `GET /api/v1/master-db/...` | 마스터 DB read-only |
| `routes.history` | `GET /api/v1/history` | 검토 이력 |
| `routes.admin` | `PUT/DELETE /api/v1/admin/...` | 시스템 설정·캐시 |

### Tier 3 — 데이터 계층

**SQLite 마스터 DB** — `backend/data/master.db`

| 도메인 | 테이블 (27 + 2 뷰) |
|---|---|
| 정규화 마스터 | `document_type` · `topic` · `topic_section` · `law` · `law_article` |
| 슬롯 | `check_item` · `check_item_applicability` · `check_item_risk` · `check_item_topic` · `check_item_law` |
| 계산형 룰 | `minimum_wage_master` · `wage_item_catalog` · `violation_type` · `recommendation_mapping` |
| 트랜잭션 | `workplace` · `employee` · `payslip_document` · `payslip_ocr_raw` · `payslip` · `payslip_line` · `llm_judgment` |
| 검토 결과 | `inspection_run` · `violation_finding` · `recommendation` · `correction_log` · `audit_case` · `audit_finding` |
| 뷰 | `v_check_item_full` · `v_inspection_full` · `v_minimum_wage_current` |

## 핵심 결정 (Architecture Decisions)

| 결정 | 이유 |
|---|---|
| SQLite 단일 파일 마스터 DB | read-heavy + 단일 사용자 MVP. 추후 Postgres 호환 |
| Pydantic 모델로 직렬화 | API 입출력 검증·결정성 |
| Streamlit admin / Next.js user | 관리자=데이터탐색, 사용자=감각적 UX 명확 분리 |
| LLM 캐시 (입력 hash → 결과) | 같은 검토 두 번 = 무료, 결정성 |
| BFF 패턴 (Next.js → FastAPI) | 브라우저에 API 키 노출 없음 |
| 슬롯 = SQL 카탈로그 (yaml fallback) | 운영 시점에 슬롯 편집 가능, 시드만 yaml |
| 룰엔진 + LLM 하이브리드 | 계산형 결정성·판단형 유연성 |
